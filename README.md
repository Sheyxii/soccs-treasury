# SOCCS Treasury

Membership, Financial, and Budget Management System for the Student Organization
of the College of Computer Studies.

This repository is the starting point for guided implementation. It contains a
minimal Flask application and the agreed folders. Authentication, MySQL access,
RBAC, audit logging, and Bootstrap integration are not implemented yet. Do not
enter operational member or financial data into this starter.

## Architecture

The application is intended to run on one designated office computer, with a
local browser, Flask/Jinja, locally stored Bootstrap assets, SQLAlchemy, and
MySQL. Waitress will be configured for deployment. Normal operation must work
without internet access.

MySQL replaces the SQLite choice in the supplied planning documents. The
architecture, installation, and backup documentation must reflect that change.

## Run the starter on Windows

Prerequisites: Git and a working Python 3 installation with pip. Initial package
installation requires internet access or a prepared local package collection.
MySQL is not needed to run the current landing page.

From this repository folder, run in PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m flask --app app run --debug --host 127.0.0.1
```

Copy .env.example only on first setup; preserve an existing .env. If the Python
launcher is unavailable, use a verified Python executable for the first command.
Open http://127.0.0.1:5000. Stop the development server with Ctrl+C. Debug mode is
for local development only. The environment's Python is invoked directly, so
PowerShell activation is optional.

Before authentication is implemented, generate a local secret:

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_hex(32))"
```

Put that value in SECRET_KEY in .env. Keep secrets out of Git. The Flask command
loads .env using python-dotenv. Database credentials in .env.example are only a
template and are not used by this initial shell. A missing secret will need to
be rejected at startup when session-based functionality is added.

## Repository map

| Path | Purpose |
| --- | --- |
| app/__init__.py | Application factory: creates and configures Flask |
| app/extensions.py | Reserved for database, migrations, login, and CSRF tools |
| app/models/ | Future database models |
| app/auth/ | Future authentication routes and forms |
| app/users/ | Future officer account functionality |
| app/main/ | First blueprint and landing-page route |
| app/templates/ | Jinja templates, including the shared base layout |
| app/static/ | Local CSS and future Bootstrap assets |
| tests/ | Future automated behavior checks |
| config.py | Application settings |
| .env.example | Safe example of local configuration |
| requirements.txt | Current Python dependencies |

Git does not store empty directories; .gitkeep files preserve template folders.
The migrations/ directory will be generated by Flask-Migrate when we integrate
the database. Do not create migration scripts manually. .venv/ and .env are
created locally and ignored by Git. Record tested dependency versions after
validating the development environment.

## Roles and boundaries

The five core roles are Coordinator, Treasurer, Auditor, President, and Adviser.
Student/member records are distinct from officer login accounts. There is no
student self-registration or sixth administrator role in the baseline.

Coordinators submit payments and expenses. Treasurers review submissions, manage
budgets, and record water-refilling income. Auditors verify payment status and
review reports/audit history. Presidents and Advisers have dashboard/report
viewing access. Server-side checks must enforce permissions on direct requests.

Authority to create officer accounts, reset passwords, and change roles still
needs definition. Start with local development account provisioning. Do not
assume that Treasurer automatically has unrestricted account administration.
